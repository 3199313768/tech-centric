# 管理工作台简化设计

## 目标

将 `/admin` 管理工作台整理为克制、清晰、适合高频管理的后台界面：保留左侧固定导航，降低装饰密度，突出资产数据和管理入口。

## 设计原则

- 保留 SpiritGarden 的柔和色彩，但减少大面积色块和宣传性内容。
- 左侧导航只负责定位和切换，内容区只承载当前页面任务。
- 总览页优先展示可操作数据，不展示说明性 Workflow 面板或状态宣传语。
- 统一标题、返回前台、返回总览和表格样式，避免页面结构各自为政。
- 不改变现有路由、数据查询、权限校验和业务功能。

## 布局

### 桌面端

- 页面使用固定左侧栏，宽度约 `13rem`，内容区占据剩余空间。
- 左侧栏从上到下依次为：品牌、主导航、返回前台。
- 移除“今日庭院状态”侧栏提示，避免无操作价值的信息占位。
- 内容区最大宽度约 `68rem`，统一水平留白。

### 移动端

- 保留顶部的导航区域，不改变现有响应式单列结构。
- 导航项显示图标和短文本，允许横向滚动，不压缩为无法识别的纯图标。
- 内容区使用较小边距，统计项改为单列排列。

## 总览页

- 页面标题为“庭院总览”，副标题只保留一句简短的资产说明。
- 顶部保留“返回前台”操作。
- 三项资产统计保留为统一的轻量数据栏：知识记录、资源链接、技能条目。
- 最近加入的知识作为唯一主内容面板，显示类型、摘要和创建时间。
- 删除“从收集到沉淀” Workflow 说明面板。
- 删除英文 `SPIRITGARDEN ADMIN`、`RECENT NOTES` 等眉题，避免中英文层级混杂。
- 统计卡保留可点击能力，继续进入对应管理页面。

## 侧栏导航

- 品牌区域只显示图标、`SpiritGarden` 和“管理工作台”。
- 当前导航项使用低对比背景和左侧强调线，非当前项保持中性。
- 导航项顺序保持：仪表盘、知识库、资源管理、技能管理、系统设置。
- “返回前台”移动到侧栏底部作为独立操作，不与业务导航混排。
- 图标继续使用现有 `lucide-react`，不增加新图标依赖。

## 子页面一致性

- 各子页面统一为：标题行、简短描述、返回总览链接、内容表格或空状态。
- 总览页之外不再重复展示大号装饰性标题区域。
- 表格保留横向滚动和现有数据字段；只调整间距、边框和行高。
- 空状态和错误状态继续使用现有语义，不改变数据和权限逻辑。

## 样式调整

- 只修改 `sg-admin*` 样式，优先复用现有 `--sg-*` 变量。
- 侧栏背景与内容背景使用相邻的低对比色，不引入新的渐变或高饱和强调色。
- 面板圆角控制在现有范围内，统计项使用统一边框和内边距。
- 页面标题字号从展示型缩小到后台标题级别，避免与前台 Hero 视觉竞争。
- 保留可见焦点态、键盘导航和足够的文字对比度。

## 验收标准

- `/admin` 仍保留固定左侧导航和全部五个导航入口。
- 总览页不再出现 Workflow 说明面板、英文眉题和“今日庭院状态”。
- 总览页仍可查看三项资产数量、最近知识记录，并通过统计项进入对应页面。
- `/admin/knowledge`、`/admin/resources`、`/admin/skills`、`/admin/settings` 保持路由和数据行为不变，视觉结构统一。
- 桌面端和移动端无横向溢出、文字重叠或导航不可用问题。
- 权限、Supabase 查询、错误状态和空状态行为不变。
- 通过相关 ESLint、TypeScript、页面测试和 `git diff --check` 检查。
